# GridGuard – Electricity Theft Investigation & Grid Anomaly Intelligence Platform

## 1. Project Overview

GridGuard is a web-based electricity theft investigation and grid anomaly intelligence platform designed to help identify suspicious electricity consumption patterns and manage investigations.

The platform provides a centralized system for managing electricity consumers, feeders, transformers, meters, electricity readings, anomalies, alerts, investigations, inspections, and digital evidence.

It uses a **hybrid database architecture**, combining PostgreSQL for structured relational data and MongoDB for flexible meter event records.

## 2. Project Objectives

- Identify unusual electricity consumption patterns.
- Detect and manage electricity anomalies.
- Generate and manage alerts.
- Support investigation and inspection workflows.
- Maintain digital evidence related to investigations.
- Provide role-based access for administrators and investigators.
- Store structured and unstructured data using relational and NoSQL databases.

## 4. Main Features and Modules

1. **Dashboard:** Displays important system statistics.
2. **Consumers:** Manages electricity consumer information.
3. **Feeders:** Manages electricity distribution feeders.
4. **Transformers:** Manages transformer information.
5. **Meters:** Manages electricity meters.
6. **Readings:** Manages electricity consumption readings.
7. **Anomalies:** Displays detected electricity anomalies and their severity.
8. **Alerts:** Manages alerts generated by the system.
9. **Investigations:** Manages electricity theft investigation cases.
10. **Inspections:** Records and manages field inspections.
11. **Evidence:** Maintains investigation-related evidence.
12. **Meter Events:** Stores and displays meter event records.

## 5. User Roles

### Admin
- Accesses the administrative modules.
- Manages consumers, feeders, transformers, and meters.
- Views dashboards, anomalies, alerts, and investigation information.
- Has administrative management permissions.

### Investigator
- Views relevant system information.
- Works with investigations, inspections, evidence, and meter events.
- Does not have administrative management access to restricted modules.

## 6. Database Architecture

GridGuard uses two databases.

### A. PostgreSQL – Relational Database

PostgreSQL stores structured information and supports relational data management.

Database name: `gridguard_db`

Main tables:

- users
- user_sessions
- consumers
- feeders
- transformers
- meters
- electricity_readings
- anomalies
- alerts
- investigations
- case_assignments
- inspections
- evidence

Database scripts are available in:

`database/postgresql/`

Important SQL files:

- `schema.sql`
- `auth_schema.sql`
- `session_schema.sql`
- `anomaly_logic.sql`
- `alert_trigger.sql`
- `investigation_trigger.sql`
- `views.sql`

### B. MongoDB – NoSQL Database

MongoDB stores flexible meter event records.

Database name: `gridguard_events`

Collection name: `meter_events`

MongoDB is used by the Meter Events module to retrieve and store meter event records.

The MongoDB connection is configured in:

`src/lib/mongodb.ts`

## 7. Installation and Setup

### Prerequisites

Install the following:

- Node.js and npm
- PostgreSQL
- MongoDB
- Git

### Step 1: Clone the repository

```bash
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd gridguard-complete
```

Replace the repository URL with your actual GitHub repository URL.

### Step 2: Install dependencies

```bash
npm install
```

### Step 3: Configure environment variables

Create a `.env.local` file in the project root.

Add the following variables with your local database connection details:

```env
DATABASE_URL=postgresql://gridguard_user:YOUR_PASSWORD@localhost:5432/gridguard_db
MONGODB_URI=mongodb://localhost:27017
```

Replace `YOUR_PASSWORD` with your PostgreSQL user's actual password.

Do not upload `.env.local` or expose database credentials on GitHub.

### Step 4: Configure PostgreSQL

Create the PostgreSQL database:

```sql
CREATE DATABASE gridguard_db;
```

Create the database user and configure its access according to your local PostgreSQL setup.

Run the SQL scripts from the `database/postgresql/` directory in the appropriate dependency order.

### Step 5: Start MongoDB

Make sure the MongoDB service is running.

The application uses the `gridguard_events` database and `meter_events` collection.

### Step 6: Start the development server

```bash
npm run dev
```

Open the application at:

http://localhost:3000

Open the login page at:

http://localhost:3000/login

## 8. Build and Production

To create a production build:

```bash
npm run build
```

To start the production server after a successful build:

```bash
npm run start
```
